  DEFECT FOUND BY THIS HARNESS (and deliberately NOT fixed this round):
  the FIRST equivalence run reported MISMATCHES: 479 / 18132 (2.6%). Cause: the
  pre-port classifier builds its event list NEWEST-FIRST (the scan walks backwards
  from the cutoff) and then weights `idx >= n - 5`, i.e. the TAIL of a
  newest-first list = the OLDEST five events — while its own comment claims
  "last-5 events double weight", i.e. the most RECENT five. The instrument has
  therefore ALWAYS weighted the oldest five events, contrary to its documentation.
  My port had reversed the list (implementing what the comment said), which
  silently changed a pre-registered instrument mid-round. That was reverted: the
  port now reproduces the existing behaviour bit-for-bit (0 mismatches) and the
  discrepancy is recorded in-code at services/sideAwareRole.ts as a DEFECT ON
  RECORD. Correcting the weighting direction changes what every Q number MEANS
  (Q's retype measurement and its n>=80 promotion gate were pre-registered against
  THIS instrument), so it is a MEASURED change for a future round, not a
  drive-by fix (MINDSET 1 + 5).
